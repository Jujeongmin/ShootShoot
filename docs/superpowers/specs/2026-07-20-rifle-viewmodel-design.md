# 1인칭 저격총 뷰모델 (설계 문서)

- **날짜**: 2026-07-20
- **선행 작업**: [2026-07-20-monkey-fbx-model-design.md](2026-07-20-monkey-fbx-model-design.md)

## 1. 목표

지금까지는 화면에 총이 전혀 보이지 않는 상태로 크로스헤어/줌만으로 조준감을 표현했다. 사용자가 제공한 저격총 3D 모델(`game/public/Rifle by Quaternius - cCAgiMOQow.glb`)을 화면에 1인칭 뷰모델로 표시해, 평소엔 화면 우하단에 총이 보이다가 조준 중에는 사라지고(스코프를 들여다보는 연출과 자연스럽게 어울림), 발사 시 반동 애니메이션이 재생되도록 한다.

## 2. 에셋

- 파일: `game/public/Rifle by Quaternius - cCAgiMOQow.glb` — glTF 바이너리, 텍스처 임베드, 애니메이션 없음(정적 메쉬 5개: Detail/ScopeHandle/Main/Barrel/Glass 재질).
- Node에서 `GLTFLoader.parse()`로 직접 로드해 확인한 사실:
  - 바운딩박스(원본 단위): `min = {x:-0.315, y:-0.669, z:-6.584}`, `max = {x:0.315, y:1.800, z:2.270}`, `size = {x:0.630, y:2.469, z:8.854}`.
  - 모델 원점(0,0,0)은 바운딩박스 중심이 아니라 한쪽(그립/방아쇠 근처로 추정)에 치우쳐 있음.
  - Draco/meshopt 등 압축 확장은 사용하지 않음(추가 디코더 설정 불필요, 순정 `GLTFLoader`로 충분).
- **파일을 `game/public/models/rifle.glb`로 이동**한다(공백 포함 파일명은 URL 참조가 지저분해지므로 정리).
- 몽키 모델과 달리 **크기 단위를 확신할 근거가 없다**(스켈레톤 본 같은 실측 기준이 없음) — 초기 추정 스케일로 시작해서 실제 렌더링 후 눈으로 조정하는 과정이 반드시 필요하다.

## 3. 아키텍처

### 3.1 로딩 — 단일 인스턴스, 한 번만 로드

원숭이와 달리 뷰모델은 화면에 **항상 하나만** 존재하므로, 로드/캐시/복제(clone) 구조가 필요 없다. 게임 부트스트랩 시 원숭이 모델 로딩과 **병렬로**(`Promise.all`) 한 번 로드하고, 곧바로 카메라의 자식으로 붙인다.

### 3.2 화면 고정 — 카메라 자식 오브젝트

이 게임의 카메라는 위치가 고정되어 있고 FOV만 바뀐다. 뷰모델 그룹을 `engine.camera.add(rifleGroup)`로 카메라의 자식으로 붙이면, 카메라 로컬 좌표계에 고정되어 항상 같은 화면 위치에 보인다(별도의 2번째 씬/카메라 오버레이 불필요).

### 3.3 배치 & 스케일

- 평소(힘파이어) 상태: 화면 우하단에 보이도록 카메라 로컬 좌표에서 오른쪽(+x) 아래(-y) 앞쪽(-z, 카메라가 -z를 바라봄) 방향으로 오프셋.
- 초기 추정값(렌더링 후 조정 대상): `SCALE = 0.08`(최종 총 길이 약 0.71 단위), 위치 오프셋 `(0.4, -0.3, -0.7)`.
- 정확한 값은 구현 중 실제 렌더링해서 화면 우하단에 자연스럽게 보이도록 눈으로 조정한다(원숭이 스케일과 달리 사전에 정확히 산출할 근거가 없는 항목).

### 3.4 조준 시 숨김

`input.onAimDown()` → 뷰모델 `visible = false`. `input.onAimUp()` → `visible = true`(발사 처리와 같은 타이밍이라, "조준 해제 = 발사 = 총이 다시 보이며 반동" 흐름이 자연스럽게 겹친다). 라운드 상태(`phase`)와는 무관하게 순수히 조준 홀드 여부로만 제어한다(메뉴/게임오버 화면에서도 굳이 숨기지 않음 — 기존 코드도 3D 씬 자체를 메뉴 중에 숨기지 않으므로 일관성 유지, 불필요한 상태 추가 지양).

### 3.5 아이들 흔들림 & 발사 반동

- **아이들**: 미세한 사인파 기반 위아래/좌우 흔들림(숨쉬기 효과) — 원숭이의 bob/sway와 같은 방식이지만 진폭은 훨씬 작게.
- **발사 반동**: `handleShot`에서 `sfx.shoot()` 호출과 같은 시점에 트리거. 짧게(예: 0.15초) 뒤로 젖혀졌다가 원위치로 돌아오는 z축 이동 + x축 회전. 아이들 흔들림과 반동은 서로 다른 오프셋을 더하는 방식으로 독립적으로 동작(원숭이처럼 상태머신 분기 없이 단순 가산).

## 4. 인터페이스

새 모듈 `game/src/gameplay/rifleViewmodel.js`가 다음을 제공한다:
```
loadRifleViewmodel(camera) -> Promise<{ setVisible(visible), triggerRecoil(), update(dt) }>
```
`game.js`가 게임 부트스트랩 시 원숭이 모델과 병렬로 이 프로미스를 기다리고, 완료되면 `input.onAimDown`/`onAimUp`에 `setVisible` 훅을 추가하고, `handleShot` 안에서 `sfx.shoot()`과 함께 `triggerRecoil()`을 호출하며, 매 프레임 `update(dt)`를 호출한다.

## 5. 비목표 (YAGNI)

- 다른 무기(에셋 여러 개, 무기 교체 기능)는 이번 범위 밖 — 나중에 필요할 때 별도로 추가.
- 총알 궤적 시각화, 머즐 플래시(총구 화염) 등 추가 이펙트는 만들지 않음(요청되지 않음).
- 스코프 오버레이(조준 시 원형 뷰네트/렌즈 이펙트)는 기존에 있다면 그대로 두고, 새로 만들지 않음(있는지 여부는 구현 중 확인).

## 6. 열린 위험

- 스케일/위치 값은 실측 근거가 약해 렌더링 후 시각적으로 조정이 필요하다 — 이번 계획에서 가장 불확실한 부분.
- 모델의 "정면" 방향(barrel이 -z인지 +z인지)도 원점 위치 추정에서 유추했을 뿐 확정은 아니라, 뒤집혀 보이면 180도 회전 보정이 필요할 수 있다.
