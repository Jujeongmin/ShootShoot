# 원숭이 레일 스폰 + 주기적 정렬 (설계 문서)

- **날짜**: 2026-07-22
- **선행 작업**: [2026-07-21-ammo-count-design.md](2026-07-21-ammo-count-design.md) — 총알이 원숭이 수보다 적은 밸런스는 관통 킬을 전제하는데, 현재 스폰(x 균등 분산 + z 랜덤 + 독립 사인 sway)은 겹침이 우연에만 의존한다. 이 기능이 그 전제를 설계로 보장한다.

## 1. 목표

라운드의 원숭이 전체를 카메라 시선 기준 "레일"(광선) 그룹으로 배치하고, 같은 레일의 원숭이들이 **주기적으로 정확히 일렬로 겹치는 순간**이 수학적으로 보장되도록 움직임을 계산한다. 플레이어는 타이밍을 재서 관통샷을 노린다.

## 2. 아키텍처

### 2.1 겹침의 수학적 정의

카메라는 (0, 1.6, 0)에 고정. 두 원숭이가 카메라에서 뻗는 같은 광선 위에 있으려면 수평으로 `x/|z|` 비율(시선 각도)이 같아야 한다. 따라서 원숭이의 위치를 각도 공간에서 정의한다:

- 원숭이 i의 수평 각도: `α_i(t) = θ_lane + A × sin(ω·t + φ_i)` (θ_lane: 레일 중심 각도, A: 각진폭, ω: 주파수, φ_i: 위상)
- 월드 x 좌표: `x_i(t) = α_i(t) × |z_i|` — **비율 `x_i/|z_i| = α_i(t)`가 되므로, 같은 레일의 두 원숭이는 `sin(ω·t + φ_i)` 값이 같아지는 순간 정확히 같은 광선 위에 놓인다.** 같은 진폭·주파수의 사인파는 위상이 달라도 주기마다 정확히 2번 교차하므로, 정렬은 우연이 아니라 보장된 주기적 사건이다.

### 2.2 레일 구성

- **그룹 분할**: 원숭이 n마리를 2~3마리 레일로 전부 분할한다. 규칙: `n % 3 == 0`이면 전부 3마리 레일, `n % 3 == 2`이면 3마리 레일들 + 2마리 레일 1개, `n % 3 == 1`이면 3마리 레일들 + 2마리 레일 2개 (n≥2에서 항상 가능; 현재 n은 3~10).
- **레일 각도**: 레일들을 `[-MAX_LANE_ANGLE, +MAX_LANE_ANGLE]`(±0.25 rad) 범위에 균등 분포시킨다.
- **깊이**: 레일 안에서 원숭이는 `FRONT_Z`(-13)부터 `BASE_DEPTH_GAP × monkeyScale` 간격으로 뒤로 배치된다. **깊이 간격에 monkeyScale을 곱하는 이유**: 카메라(y=1.6)가 위에서 내려보므로 관통 광선은 기울어져 있다 — 원숭이가 작아지는 후반 라운드에서 깊이 간격이 그대로면 앞 원숭이 몸을 지난 광선이 뒤 원숭이 아래로 빠져 수직으로 어긋난다. 간격을 스케일에 비례시키면 어느 라운드에서든 앞 원숭이의 머리/상체를 조준한 광선이 뒤 원숭이 몸통을 지난다(관통 조준점이 자연히 머리 쪽이 되어 기존 헤드샷 보너스와 시너지).
- **위상**: 레일 안의 k마리에게 `φ_i = i × 2π/k`. k=2면 (0, π) — 둘이 반대 방향으로 움직이다 레일 중심에서 교차(주기당 2번). k=3이면 (0, 2π/3, 4π/3) — 세 쌍이 서로 다른 시점에 각각 주기적으로 교차해 관통 기회가 스태거된다(3마리 동시 정렬은 일어나지 않지만, 2마리 관통이면 총알 밸런스상 충분하다 — 관통 1회당 +1킬).
- **주파수**: `ω = SWAY_FREQUENCY_PER_SPEED × monkeySpeed` — 기존 난이도 곡선(라운드당 speed 증가)이 그대로 정렬 창의 속도/빈도에 반영된다. 초기값 기준 정렬 주기는 레일당 약 3~4초.

### 2.3 모듈 구조

- 새 순수 모듈 `game/src/gameplay/laneLayout.js`:
  ```
  computeLaneLayout(monkeyCount, monkeySpeed, monkeyScale) ->
    [{ x, y, z, swayAmplitude, swayFrequency, swayPhase }, ...]
  ```
  상수(`FRONT_Z=-13`, `BASE_DEPTH_GAP=2.5`, `MAX_LANE_ANGLE=0.25`, `ANGULAR_SWAY_AMPLITUDE=0.038`, `SWAY_FREQUENCY_PER_SPEED=1.8`)는 모듈 안에 둔다(`obstacles.js`의 PLACEMENTS와 같은 방식). 순수 함수이므로 Vitest로 "같은 레일 원숭이들의 특정 시각 `x/|z|` 비율 일치"를 수학적으로 검증한다.
- `game/src/gameplay/monkey.js`: `createMonkey`가 `sway: { amplitude, frequency, phase }` 옵션을 받는다. 미지정 시 기존 동작(진폭 0.5, 주파수 speed, 랜덤 위상)과 동일한 기본값. `updateIdle`의 sway 계산만 이 값들을 쓰도록 바뀌고, bob(상하 흔들림)·taunt(까불기)는 불변.
- `game/src/gameplay/targetManager.js`: `spawnRound`가 기존 `computeSpawnPosition` 대신 `computeLaneLayout` 결과로 각 원숭이의 위치와 sway 파라미터를 전달한다.

## 3. 인터페이스 변경 요약

- `game/src/gameplay/laneLayout.js` (신규): `computeLaneLayout(monkeyCount, monkeySpeed, monkeyScale) -> Array<{x, y, z, swayAmplitude, swayFrequency, swayPhase}>`.
- `game/src/gameplay/monkey.js`: `createMonkey({ ..., sway })` — 선택적 `sway` 옵션 추가, 기본값은 기존 동작 유지.
- `game/src/gameplay/targetManager.js`: `spawnRound`가 `computeLaneLayout`을 사용, `computeSpawnPosition` 제거.

## 4. 비목표 (YAGNI)

- 정렬 순간을 UI로 알려주는 인디케이터(반짝임, 소리 등)는 만들지 않음 — 플레이어가 눈으로 타이밍을 잰다.
- 원숭이 간 충돌 회피/물리 시뮬레이션은 만들지 않음 — 겹침이 목적이므로 시각적으로 겹쳐 보이는 것이 정상.
- 레일 구성을 라운드 중간에 바꾸는 기능은 만들지 않음 — 스폰 시 한 번 계산, 라운드 내내 유지.
- 3마리 레일의 "3마리 동시 정렬"은 보장하지 않음 — 쌍별 정렬로 충분.

## 5. 열린 위험

- 상수들(FRONT_Z, 깊이 간격, 각진폭, 주파수 계수)은 초기 추정치 — 원숭이 모델의 실제 히트박스 높이/폭과 맞물리므로, 구현 시 실제 레이캐스트로 "정렬 순간에 관통이 실제로 판정되는지"를 검증하고 필요하면 조정해야 한다(특히 수직 방향: 앞 원숭이의 어느 높이를 쏴야 뒤 원숭이에 닿는지).
- 기존 엄폐물(모래주머니 참호)이 일부 레일의 낮은 탄도를 가릴 수 있다 — 이는 엄폐물 기능의 의도된 상호작용(각도를 찾는 재미)으로 보고 그대로 두되, 실제 플레이에서 특정 레일이 완전히 막혀 라운드 클리어가 불가능해지는 경우가 발견되면 레일 각도 범위나 엄폐물 배치를 조정한다.
- 정렬 주기(~3-4초)와 라운드 제한시간(30초~12초)의 균형 — 후반 라운드(제한시간 12초, 레일 4개)에서 모든 레일의 정렬을 기다릴 시간이 부족할 수 있다. ω가 speed에 비례해 후반엔 정렬이 더 자주 오므로 상쇄될 것으로 예상하지만, 실플레이 확인 필요.
