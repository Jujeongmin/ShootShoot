# 구조물 추락사 — 상자 기둥 탑 붕괴 (설계 문서)

- **날짜**: 2026-07-22
- **선행 작업**: [2026-07-20-obstacles-design.md](2026-07-20-obstacles-design.md)(장애물 시스템), [2026-07-22-lane-spawn-alignment-design.md](2026-07-22-lane-spawn-alignment-design.md)(레일 스폰)
- **원래 논의 위치**: [2026-07-21-ammo-count-design.md](2026-07-21-ammo-count-design.md) 브레인스토밍 중 규모가 커서 별도 스펙으로 분리됨.

## 1. 목표

기존 지면 장애물(모래주머니 2 + 상자 2) 중 상자 2개 배치를 "상자 기둥 탑"으로 교체한다. 탑은 기둥(상자 2개) 위에 모래주머니를 눕혀 만든 발판, 그 위에 서있는 원숭이 1마리로 구성된다. 기둥 중 하나만 맞아도 탑이 즉시 무너지고, 위에 있던 원숭이가 추락사한다 — 직접 조준 외의 대안 킬 경로를 제공한다.

## 2. 아키텍처

### 2.1 탑 구조 (기존 에셋 재활용, 새 에셋 없음)

- 탑 하나 = 기둥 2개(상자 2개를 세로로 쌓아 만든 기둥, 서로 옆으로 떨어져 배치) + 그 위를 가로지르는 발판(모래주머니를 눕혀서 사용) + 발판 위에 서있는 원숭이 1마리.
- 탑은 정확히 **2개**, 기존 상자 단독 배치 위치(대략 `x: 0.5, z: -7.5`와 `x: -1.5, z: -8.5`)를 그대로 재사용한다. 기존 모래주머니 2개(지면 엄폐물)는 그대로 유지한다.
- 정확한 크기/간격/높이 배율은 초기 추정치이며, 실제 렌더링 후 "기둥 사이 간격이 발판을 지탱하는 것처럼 보이는지", "원숭이가 발판 위에 자연스럽게 서 있는지"를 시각적으로 조정한다(기존 `obstacles.js`의 크레이트/모래주머니 배율 조정과 같은 방식).

### 2.2 붕괴 판정 — 기둥 중 하나만 맞아도 즉시

- 기둥 메쉬는 레이캐스트 대상에 포함되고(기존 상자와 달리 **관통 대상이 아니라 명중 판정 대상**), 각각 `pillarId`(어느 탑 소속인지 식별하는 `towerIndex` 포함)를 `userData`에 갖는다.
- `handleShot()`의 명중 분류가 기존 "원숭이(관통)" / "장애물(차단)" 이분법에서 "원숭이(관통)" / "기둥(명중 판정 후 정지)" / "그 외 장애물(차단)" 삼분법으로 확장된다. 기둥에 맞으면 그 지점에서 순회를 멈추고(더 먼 원숭이는 이번 샷에서 제외 — 기존 장애물 차단과 동일한 관통 규칙), 해당 탑의 붕괴를 트리거한다.
- 어느 기둥이든 하나만 맞으면 그 탑은 즉시 무너진다 — 두 기둥을 다 맞힐 필요 없음.

### 2.3 붕괴 연출 + 원숭이 추락사

- 탑이 무너지면: 기둥/발판이 짧게(약 0.3초) 기울어지며 사라지는 간단한 절차적 트윈(기존 원숭이 사망 애니메이션, HUD 점수 팝업과 같은 수준의 단순 트윈 — 물리 시뮬레이션 아님).
- 그 탑 위에 있던 원숭이는 **기존 `monkey.hit(part)`를 그대로 재사용**해서 사망 처리한다(회전하며 사라지는 기존 사망 애니메이션 재사용, 새 애니메이션 상태를 만들지 않음) — `handleShot`이 직접 그 원숭이의 `hit()`을 호출한다(레이캐스트가 원숭이를 직접 맞힌 게 아니라 게임 로직이 트리거하는 것).
- 점수: 고정 보너스 점수(`CONFIG.score.towerCollapseBonus`, 초기값 200 — 몸통 명중 100과 헤드샷 250 사이) — 총알이 원숭이에 직접 닿은 게 아니므로 머리/몸통 구분 없이 고정값. 콤보/연속 배율 등 기존 점수 시스템과는 별개로 처리한다(관통 히트가 아니므로).
- 총알은 이미 이 샷으로 1발 소모된다(기존 `handleShot`의 발사 시 소모 로직 그대로).

### 2.4 원숭이 배치와 레일 시스템의 관계

- 라운드마다 **정확히 2마리**(탑 개수만큼)가 탑 위에 배치되고, 나머지(`monkeyCount - 2`마리)는 기존 레일 시스템(`computeLaneLayout`)으로 배치된다. 최소 라운드 원숭이 수는 3(1라운드 기준)이므로 레일에는 항상 최소 1마리가 남는다(`computeLaneLayout`은 이미 1마리 케이스를 지원함).
- 탑 위 원숭이는 **좌우로 흔들리지 않고 가만히 서 있는다** — 기존 `createMonkey`의 `sway` 옵션(레일 스폰에서 이미 추가됨)에 `amplitude: 0`을 넘겨서 구현한다. 상하 bob(숨쉬기)과 까불기(taunt)는 다른 원숭이와 동일하게 재생된다. 레일 정렬 대상이 아니므로 관통샷의 대상이 되지 않는다 — 탑 위 원숭이를 잡는 방법은 (a) 직접 조준해서 맞히거나 (b) 기둥을 쏴서 무너뜨리는 두 가지다.

## 3. 인터페이스 변경 요약

- `game/src/gameplay/obstacles.js`: 상자 단독 배치 2곳을 탑으로 교체(기둥 2개 + 발판). `getBlockingMeshes()`는 그대로 모래주머니만 반환. 새로 `getPillarMeshes()`(기둥 메쉬, `userData.towerIndex` 포함) 추가. `getTowerSlots()`(탑 위 원숭이 배치 위치, `{ x, y, z, towerIndex }[]`) 추가. `collapseTower(towerIndex)`(붕괴 연출 트리거) 추가.
- `game/src/gameplay/targetManager.js`: `spawnRound`가 탑 슬롯 2곳에 원숭이를 먼저 배치(`sway: { amplitude: 0, ... }`)하고, 나머지를 `computeLaneLayout`으로 배치. `findMonkeyAtTower(towerIndex)`(탑 위 원숭이 조회) 추가.
- `game/src/gameplay/game.js`: `handleShot()`의 레이캐스트 대상에 `obstacles.getPillarMeshes()` 추가, 명중 분류를 삼분법으로 확장, 기둥 명중 시 `obstacles.collapseTower(towerIndex)` + `targetManager.findMonkeyAtTower(towerIndex).hit(...)` + 고정 보너스 점수 지급.
- `game/src/config.js`: `score.towerCollapseBonus: 200` 추가.

## 4. 비목표 (YAGNI)

- 실제 물리 기반 붕괴 시뮬레이션(강체 물리, 파편 튐)은 만들지 않음 — 단순 절차적 트윈.
- 원숭이의 별도 "추락" 애니메이션(기존 사망 애니메이션과 다른 낙하 모션)은 만들지 않음 — 기존 `hit()` 애니메이션 재사용.
- 탑 위 원숭이가 흔들리거나 이동하는 기능은 만들지 않음 — 고정.
- 두 기둥을 모두 맞혀야 무너지는 옵션은 만들지 않음 — 하나만 맞아도 즉시 붕괴.
- 탑 배치를 라운드마다 다른 위치로 바꾸는 기능은 만들지 않음 — 고정 2곳.
- 탑이 무너진 뒤 다시 세워지거나 재사용되는 기능은 만들지 않음 — 한 라운드 안에서 무너지면 그 라운드 내내 무너진 채로 남는다(다음 라운드 시작 시 다시 온전한 탑으로 리셋됨 — `spawnRound`가 매 라운드 새로 배치하므로 자동으로 해결됨).

## 5. 열린 위험

- 탑의 정확한 크기/간격/높이는 초기 추정치 — 기둥 사이 간격, 발판 높이, 원숭이가 자연스럽게 서 보이는 위치는 실제 렌더링 후 조정이 필요하다(기존 obstacles 스펙의 "열린 위험"과 동일한 성격).
- 기둥 명중 판정이 기존 "원숭이(관통) / 장애물(차단)" 이분법에서 삼분법으로 늘어나면서 `handleShot`의 레이캐스트 분류 로직이 조금 더 복잡해진다 — 기존 관통/차단 규칙(원숭이는 계속 관통, 장애물은 차단)과 충돌하지 않도록 구현 시 주의가 필요하다.
- 고정 보너스 점수(200)는 초기 추정치 — 실제 플레이해보면서 밸런스 조정이 필요할 수 있다. 다만 기둥 하나만 맞으면 확정 1킬이라는 점에서, 총알이 원숭이 수보다 적은 현재 밸런스(관통/정렬 타이밍에 의존)에 비해 상대적으로 "쉬운" 킬 경로가 될 수 있어, 오히려 난이도를 낮추는 효과가 있을 수 있다 — 플레이테스트로 확인 필요.
