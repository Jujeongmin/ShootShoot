# 구조물 붕괴 물리 설계 (2026-07-29)

## 문제

붕괴가 부자연스럽다. 지금은 구조물 그룹 하나를 0.3초에 걸쳐 z축으로 90° 기울이고
0.6 내리면서 투명하게 만든다. 조각이 나뉘지 않으니 통짜 판이 쓰러지는 것처럼 보이고,
어디를 맞혔든 항상 같은 방향으로 같은 모양으로 넘어간다. 총알이 준 충격이 화면에
전혀 안 나타난다.

## 목표

맞은 지점에서 조각이 튀어나가 중력으로 떨어지고 바닥에서 튄 뒤 멈추게 한다.
가까운 조각일수록 세게 날아가고, 아래를 맞히면 앞으로 구른다.

## 하지 않는 것

- **물리 엔진 도입.** 의존성은 `three` 와 `fflate` 뿐이고 그대로 둔다.
- **조각끼리 충돌.** 조각은 서로 통과한다. 한 구조물이 다섯 조각뿐이라 눈에 잘 안 띈다.
- **원숭이가 같이 떨어지는 것.** 발판 위 원숭이는 지금처럼 죽는 연출만 한다.
- 먼지, 파편 소리, 카메라 흔들림.
- 모델을 더 잘게 쪼개는 것 (아래 "조각 수 한계" 참고).
- 무너진 자리에 잔해가 영구히 쌓이는 것. 잔해는 멈춘 뒤 사라진다.

## 현재 구조 (확인함)

- `obstacles.js` 가 타워 2개와 참호 2개를 만든다. 각각 `THREE.Group` 하나에 담긴다.
- 타워 그룹의 자식: 상자 인스턴스 4개(2단 × 2줄)와 발판 1개.
- 참호 그룹의 자식: 자루벽 인스턴스 1개.
- `advanceCollapse(structure, dt)` 가 그룹의 `rotation.z`, `position.y`, 재질 `opacity`
  를 한꺼번에 움직이고 `t >= 1` 에서 `group.visible = false` 로 끝낸다.
- `reset()` 이 회전·위치·불투명도를 되돌리고 다시 보이게 한다. 라운드마다 불린다.
- 각 메시의 재질은 로드 시 `clone()` 돼 있다. 구조물마다 따로 페이드할 수 있다.
- `collapseStructure({ kind, index })` 가 유일한 진입점이고, 이미 무너지는 중이면 무시한다.
- `obstacles.update(scaledDt)` 로 불린다 — 마지막 처치 슬로모가 이미 반영된 델타다.
- `GROUND_Y = -1.0` 이 섬 윗면이다.

### 조각 수 한계 (실측)

`crate.glb` 와 `sack-trench.glb` 는 **둘 다 메시가 하나**다 (glb 의 JSON 청크에서 확인:
`meshes: 1`). 그래서 조각 단위는 **씬에 배치된 인스턴스**가 될 수밖에 없다:

| 구조물 | 조각 |
|---|---|
| 타워 | 상자 4개 + 발판 1개 = **5조각** |
| 참호 | 자루벽 **1조각** |

참호는 한 덩이로 굴러간다. 자루 하나하나가 흩어지려면 모델을 쪼개야 하고, 그건 이
스펙 밖이다. 타워가 주 표적이고 조각이 다섯이라 효과는 거기서 나온다.

## 설계

### 1. 순수 물리 모듈 — `game/src/gameplay/debris.js`

three.js 를 쓰지 않는다. 평범한 `{ x, y, z }` 객체만 주고받으므로 프레임 루프 밖에서
테스트된다.

```js
createDebrisBody({ position, rotation, velocity, spin, restY })
  -> { step(dt), getPosition(), getRotation(), isResting() }

impactImpulse(pieceCenter, impactPoint, strength)
  -> { velocity: {x,y,z}, spin: {x,y,z} }
```

**`step(dt)`**

1. `velocity.y -= GRAVITY * dt`
2. 위치와 회전을 속도·각속도로 적분한다
3. `position.y` 가 `restY` 아래로 내려가면 `restY` 로 끌어올린다 — 프레임이 길어도
   바닥을 뚫지 않는다
4. 그 지점에서 남은 낙하 속도가 `REST_SPEED` 보다 작으면 **멈춘다**: 속도와 각속도를
   0으로 만들고 `resting` 을 세운다
5. 아니면 튄다: `velocity.y` 를 뒤집고 `RESTITUTION` 을 곱한다. 수평 속도에 마찰,
   각속도에 감쇠를 건다
6. `resting` 이 서면 이후 `step` 은 아무것도 하지 않는다

**`impactImpulse`**

- 방향은 명중점에서 조각 중심으로 향한다. 조각은 맞은 곳의 반대편으로 밀린다.
- 속력은 `strength / (1 + 거리)` 다. 가까운 조각이 세게 난다. 거리는 최소값으로
  바닥을 깔아 명중점과 조각 중심이 겹칠 때 무한대가 되지 않게 한다.
- 위로 띄우는 성분을 더한다. 안 그러면 전부 수평으로 미끄러진다.
- **회전은 지렛대에서 나온다.** 조각 중심보다 아래를 맞으면 밀리는 방향으로 앞구른다.
  회전축은 미는 방향과 수직인 수평축이고, 크기는 `속력 × (조각 중심 y − 명중점 y)`
  에 비례한다. 중심 높이를 정확히 맞히면 회전이 0이다. 난수를 쓰지 않으므로 같은
  사격은 항상 같은 붕괴를 낸다.

### 2. `obstacles.js` 의 붕괴 재작성

구조물마다 `pieces` 배열을 만든다. 각 조각은 `{ object, homeParent, homePosition, homeQuaternion, restOffset, materials, body, restedFor }` 다.

- `restOffset` 은 로드 시 `THREE.Box3().setFromObject(object)` 로 한 번 잰다.
  조각 원점에서 가장 아래 면까지의 거리이며, `restY = GROUND_Y + restOffset` 이 된다.
  이걸 안 재면 조각 원점이 바닥에 닿아 절반이 땅에 파묻힌 채 멈춘다.
- 붕괴가 시작되면 각 조각을 `scene.attach(object)` 로 그룹에서 떼어낸다. three.js 의
  `attach` 는 월드 변환을 보존해서 조각이 그 자리에 그대로 남는다. 그 뒤로는 조각이
  그룹 회전에 끌려다니지 않는다.
- 매 프레임 `body.step(dt)` 를 돌리고 결과를 `object.position` 과 `object.rotation` 에
  넣는다.
- 조각이 멈추면 `restedFor` 를 센다. `DEBRIS_HOLD_SECONDS` 동안 그대로 두고, 이어서
  `DEBRIS_FADE_SECONDS` 에 걸쳐 재질 `opacity` 를 0으로 내린 뒤 숨긴다.
- `reset()` 은 조각을 `homeParent.attach(object)` 로 되돌리고 저장해 둔 로컬 위치·회전,
  불투명도, 가시성을 복원한다.

구조물의 `collapsing` / `collapsed` 플래그와 그 의미는 그대로다. `getBlockingMeshes`,
`getPillarMeshes`, `findStructuresInBox` 도 안 바뀐다 — 무너지는 중인 구조물을 이미
걸러낸다.

### 3. 명중점 전달

`collapseStructure({ kind, index })` 에 `impactPoint` 를 더한다. 부르는 곳은 둘이다.

- **총알** — `handleWeaponShot` 은 이미 원숭이별 최근접 교차점을 `firstPointByMonkey` 에
  모은다. 같은 방식으로 타워별 최근접 교차점 표를 하나 더 만들어 `applyTowerCollapse` 로
  넘긴다.
- **바주카** — `resolveBazookaImpact` 는 폭심(`impactPoint`)을 이미 들고 있다. 직격 타워와
  폭발 범위에 든 구조물 전부 같은 값을 쓴다.

명중점이 없으면 구조물 중심에서 카메라 쪽으로 조금 당긴 지점을 기본값으로 쓴다.
그러면 조각이 카메라 반대편으로 밀려 지금과 비슷한 방향이 된다.

## 테스트

`test/debris.test.js`:

- 중력으로 떨어진다 — 한 번 `step` 하면 y가 내려가고 속도가 더 음수가 된다
- 바닥에서 튄다 — 튄 뒤 속도가 위를 향하고 크기는 이전보다 작다
- 튈수록 약해져 결국 멈춘다 — 여러 번 돌리면 `isResting()` 이 참이 된다
- 멈춘 뒤에는 더 안 움직인다 — 위치가 그대로다
- 프레임이 아주 길어도 `restY` 아래로 안 내려간다
- `impactImpulse` 가 명중점 반대편으로 민다 — 속도와 (조각 중심 − 명중점)의 내적이 양수
- 가까운 조각이 더 빠르다 — 거리 1과 거리 5의 속력 비교
- 위로 띄운다 — 같은 높이에서 밀어도 `velocity.y > 0`
- 중심보다 아래를 맞히면 회전이 생기고, 위를 맞히면 부호가 뒤집힌다
- 정확히 중심 높이를 맞히면 회전이 0이다

기존 153개는 그대로 통과해야 한다.

## 육안 확인 항목 (사용자)

1. 타워를 쏘면 상자 다섯 조각이 따로 날아가는가
2. 맞힌 쪽 반대편으로 밀려나는가 — 왼쪽 기둥을 쏘면 왼쪽에서 오른쪽으로
3. 조각이 바닥에서 한 번 튀고 멈추는가, 땅에 파묻히지 않는가
4. 멈춘 조각이 잠깐 있다가 사라지는가
5. 참호는 한 덩이로 굴러가는가 (조각이 하나뿐인 게 의도다)
6. 바주카로 부술 때도 폭심 반대편으로 날아가는가
7. 마지막 처치 슬로모 중에 붕괴가 같이 느려지는가
8. 다음 라운드가 시작되면 구조물이 원래 자리에 멀쩡히 돌아오는가
