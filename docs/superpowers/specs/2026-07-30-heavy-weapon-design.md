# 별 4개 무기 '중화기' 설계 (2026-07-30)

## 문제

상점 무기가 별 1·2·3·5 로 뛴다. 별 4개 자리가 비어 있다.

| 무기 | 별 | 가격 |
|---|---|---|
| 기본 소총 | 1 | 0 |
| 전기총 | 2 | 500 |
| 저격소총 | 3 | 2000 |
| **(빈자리)** | **4** | |
| 레이건 | 5 | 6000 |

## 결정된 것

| | |
|---|---|
| id | `heavy` |
| 이름 | 중화기 |
| 모델 | `/models/Rifle.fbx` (지금 아무 데서도 안 쓰이는 파일) |
| 데미지 | 4 |
| 가격 | 4000 |
| 상점 위치 | 저격소총과 레이건 사이 |

`Rifle.fbx` 를 고른 이유는 이미 저장소에 있고 참조하는 곳이 없어서다. 기본 소총은
같은 이름의 다른 파일 `rifle.glb` 를 쓴다 — 둘은 별개다.

## 코드에서 확인한 사실

새 무기는 `config.js` 의 `weapons` 배열에 항목 하나를 넣는 것이 전부다. 아래는
그렇게 해도 되는 이유다.

- 상점 페이징은 `weapons.length` 를 기준으로 한다 (`shopPanel.js:123`). 항목이 늘면
  다음 버튼과 하단 점 표시가 따라온다.
- 별은 `MAX_DAMAGE_PIPS = 5` 로 그려진다. `damage: 4` 면 네 개가 찬다.
- `weaponStore` 는 소유 id 를 문자열 배열로 들고 있고, 모르는 id 는 그냥 미보유가 된다.
  **기존 세이브가 안 깨진다.**
- `weaponButtonState(weapon, gold)` 는 장착·보유·가격만 본다. 새 무기도 같은 흐름을 탄다.

## 남은 두 가지

### `scale` 은 띄워 봐야 안다

FBX 무기들의 배율이 제각각이다 — 전기총 `0.00148`, 저격소총 `0.00061`, 레이건
`0.00211`. 같은 팩에서 나왔지만 모델 길이가 달라 뷰모델에 맞추는 값이 다르다.

**`0.00148` 로 시작한다.** 전기총과 길이가 비슷한 계열이기 때문이다. 사용자가 보고
크면 줄이고 작으면 키운다. `position` 과 `rotation` 은 다른 무기와 같은 값
(`{ x: 0.4, y: -0.3, z: -0.7 }`, 회전 0) 으로 두고 시작한다.

### 상점 그림은 사용자가 굽는다

`image: '/images/weapons/heavy.png'` 를 가리키되, 파일은 나중에 들어온다.
`artwork()` 가 깨진 이미지를 숨기므로 그림이 없어도 상점은 정상으로 뜬다. 자리만 빈다.

굽는 순서: `game/thumb.html` 로 512×512 투명 PNG 를 뽑고 → **반드시**
`tools/crop-weapon-art.mjs` 를 한 번 돌린다. 안 돌리면 정사각 캔버스 여백 때문에
상점에서 그림이 작게 나온다.

## 테스트

`config.js` 는 데이터라 단위 테스트가 붙을 자리가 마땅치 않다. 대신 무기 배열 전체를
한 번 검증하는 테스트를 새로 넣는다. 이번 무기만이 아니라 앞으로 무기를 더 넣을 때도
그물이 된다.

- id 가 중복되지 않는다
- 가격이 배열 순서대로 오름차순이다
- 데미지가 배열 순서대로 오름차순이다
- 모든 무기에 `id` `name` `model` `format` `damage` `price` `image` `scale`
  `position` `rotation` 이 있다
- `format` 은 `'glb'` 또는 `'fbx'` 다
- `scale` 이 0보다 크다
- 중화기가 데미지 4로 존재한다

## 건드리지 않는 것

`shopPanel.js`, `weaponStore.js`, `weaponButtonState.js`, `weaponViewmodel.js`,
`shooting.js`. 전부 무기 개수에 대해 이미 일반적이다.
