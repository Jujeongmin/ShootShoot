## 사용자 상시 지시사항

- **애매하면 혼자 판단하지 말고 물어볼 것.** 사용자가 여러 번 명시적으로 요구했다.
- **토큰을 아낄 것.** 불필요한 재확인·장황한 요약 금지.
- **작업 브랜치는 `master` 직접 커밋.** worktree 쓰지 말 것 (네 세션 연속 명시적 선택).
- 게임 육안/청각 확인은 **사용자가 직접 한다.** 확인해 달라고 요청만 하면 된다.
- 기능 작업은 브레인스토밍 → 스펙 → 계획서 → 서브에이전트 실행(SDD) 순서를 좋아한다.
  실행 방식을 물으면 대체로 "1번"(서브에이전트)을 고른다.

## 환경 제약 (중요)

- **브라우저 창이 이 환경에서 안 열린다.** `computer{action:"screenshot"}` 이
  `the Browser pane is not displayed` 로 실패한다. 레이아웃·애니메이션·연출은
  **전부 사용자 육안 확인 항목**이다. `read_console_messages` 는 된다 (에러 확인용).
- 검증 가능한 것: `npm test`, `npm run build`, `curl`, `node -e`, 파일 직접 읽기.
- **`python` 이 없다.** Windows 스토어 스텁만 있어서 heredoc 스크립트가 조용히 안 돈다.
  파일 수정은 Edit 툴이나 `node -e` 를 쓸 것.
- ~~`git commit` 이 매번 worktree Permission denied 를 뱉는다~~ → **해결됨.**
  `.git/worktrees/weapon-shop-purchase-brainstorm-58a5a7` 를 지웠다. `git fsck` 깨끗.
- **원격 저장소가 없다.** `git remote -v` 가 비어 있고 전부 로컬 `master` 에만 있다.
  사용자가 "놔둬"라고 했으므로 만들지 말 것.

### 개발 서버

포트 5173은 **다른 프로젝트(TowerWar)의 vite 서버**가 잡고 있다. 우리 서버는
`autoPort` 로 5174에 뜬다. `.claude/launch.json` 이 `--host` 를 붙이므로 LAN 노출된다.

```
이 PC:      http://127.0.0.1:5174/
다른 기기:  http://192.168.1.82:5174/
```

LAN IP는 바뀔 수 있다. `ipconfig | findstr IPv4` 로 확인할 것.
`preview_start` 가 돌려주는 포트(5~6만번대)는 **브라우저 패널 내부 프록시 포트**라
일반 브라우저로는 안 열린다. 사용자에게는 반드시 5174를 알려줄 것.

### 2. 하늘 배경 — 구름, 먼 섬, 새

[설계](2026-07-29-sky-background-design.md) · [계획](../plans/2026-07-29-sky-background.md)

`skyMotion.js`(순수) + `skyDecor.js`(three.js). 이후 사용자 요청으로 두 번 더 밀었다.

최종 수치:

| | 값 |
|---|---|
| 카메라 far | 1400 |
| fog | `Fog(0x87ceeb, 80, 900)` |
| 구름 z | -400 ~ -560, 크기 19~43 |
| 구름 배치/랩 x | 250 / 360 → **420 / 620** |
| 먼 섬 z | -570 ~ -680, 폭 90~200 |
| 새 | 5마리 V 대형, z -150, 24초 주기 |

**중요한 함정:** fog 색이 배경색과 같아서 `fog.far` 를 넘긴 것은 흐려지는 게 아니라
**통째로 사라진다.** 구름을 뒤로 밀 때마다 `fog.far` 와 `camera.far` 를 같이 밀어야
하고, 먼 섬은 65~85% 혼합 구간에 다시 맞춰야 실루엣으로 남는다. 셋이 한 몸이다.

### 3. 나무상자 관통

[설계](2026-07-29-crate-penetration-design.md) · [계획](../plans/2026-07-29-crate-penetration.md)

- `partitionShotPath(entries)` — 멈춤 규칙 순수 함수 (원숭이 통과 / 상자 통과 / 참호 정지)
- 상자를 사격 방향으로만 납작하게 (`CRATE_DEPTH_RATIO = 0.22`). **x·y 는 절대 안 건드린다** —
  단 높이·발판·`monkeySlot` 이 전부 y 기준이다
- 지나간 타워를 전부 무너뜨린다 (`hitTowerIndex` → `towerIndices` 목록)

**최종 리뷰가 잡아낸 것:**
- 점수 팝업이 살아남은 원숭이에 붙던 버그 — 고쳤다. 직격은 실제로 죽였을 때만 앵커를 잡는다
- **한 발로 타워 둘 관통은 지금 배치로 불가능하다.** 카메라가 원점 고정이라 모든 사격선이
  `x = k·z` 인데 타워 0(x +0.22~+2.78)과 타워 1(x -5.78~-3.22)이 x=0 반대편이다.
  목록과 테스트는 유지하되 스펙에 "지금 배치로는 최대 1개"라고 명시했다

### 4. 구조물 붕괴 물리

[설계](2026-07-29-collapse-physics-design.md) · [계획](../plans/2026-07-29-collapse-physics.md)

`debris.js`(순수 적분기) + `obstacles.js` 재작성. 조각을 `scene.attach` 로 그룹에서
떼어내 각자 낙하시킨다.

이후 사용자 피드백으로 두 번 조정 — 날아가는 게 부자연스럽다고 해서 **둘 다 제자리에서
주저앉게** 바꿨다:

| | 임펄스 배율 | 가라앉는 깊이 |
|---|---|---|
| 타워 | 0.25 | 0.3 |
| 참호 | 0.12 | 0.45 |

- 타워 배율을 0으로 안 한 이유: 조각 다섯이 **서로 충돌하지 않으므로** 안 밀면 같은
  자리에 겹쳐 한 덩이로 뭉개진다
- 참호는 `sack-trench.glb` 가 메시 하나라 조각이 **하나뿐**이다. 더 못 쪼갠다
- **착지 보정**: `restY` 는 회전 전 바운딩 박스로 잰 값이라 조각이 뒹굴면 어긋난다.
  멈추는 프레임에 한 번만 실제 회전된 `Box3` 로 다시 잰다. 그리고 멈춘 뒤에는
  body 값을 오브젝트에 **복사하지 않는다** (`piece.settled`) — 안 그러면 보정이
  다음 프레임에 지워진다

## 확정된 설계 결정 (고치지 말 것)

- **초반 라운드 반복 골드 파밍은 열어둔다.** 판을 나가면 라운드가 1로 리셋되고 어느
  라운드를 깼는지 기록이 없어서 무한 파밍이 가능하다. 사용자에게 보고했고 **막지
  않기로 결정했다.** 리뷰어가 지적하면 의도된 것이라고 답할 것.
- 장전 슬로모 desync — 그대로 둔다 (위 1번 참고).
- `resetStructure` 가 아직 `group.visible` / `group.rotation.z` 를 만진다. 새 붕괴
  경로에서는 무해한 잔재로 확인됨. 그대로 둔다.

## 남은 것

### 알려진 문제

- **속도와 체력에 상한이 없다.** `difficulty.js` 에서 속도는 `0.5 + n×0.08`, 체력은
  `1 + floor(n/2)` 로 무한히 오른다. 원숭이 수만 10에서 멈춘다. 장전 0.8초 때문에
  초당 1.25발이 상한이라 어느 시점에 진행이 막힌다. 사용자가 아직 결정 안 함.
- 타워 발판이 레이캐스트 대상이 아니다. 발판 밴드를 쏘면 `sfx.miss()` 가 난다.
  이 브랜치가 만든 게 아닌 기존 동작.
- 기둥을 얇게 해서 **발판이 기둥보다 앞뒤로 0.49씩 튀어나온다.** 사용자가 보고
  "문제없다"고 했으므로 현 상태 유지.
