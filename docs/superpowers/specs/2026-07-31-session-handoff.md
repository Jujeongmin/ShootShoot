# 세션 인수인계 (2026-07-31)

이 문서만 읽으면 다음 세션에서 작업을 이어갈 수 있다.
직전 문서는 [2026-07-30-session-handoff.md](2026-07-30-session-handoff.md) 이며,
거기 적힌 사용자 지시사항과 환경 제약은 **여전히 유효하다** — 아래에 다시 적는다.

## 사용자 상시 지시사항

- **애매하면 혼자 판단하지 말고 물어볼 것.** 사용자가 여러 번 명시적으로 요구했다.
- **토큰을 아낄 것.** 불필요한 재확인·장황한 요약 금지.
- **작업 브랜치는 `master` 직접 커밋.** worktree 쓰지 말 것 (다섯 세션 연속 명시적 선택).
- 게임 육안/청각 확인은 **사용자가 직접 한다.** 확인해 달라고 요청만 하면 된다.
- 기능 작업은 브레인스토밍 → 스펙 → 계획서 → 서브에이전트 실행(SDD) 순서를 좋아한다.
  실행 방식을 물으면 대체로 "1번"(서브에이전트)을 고른다.
- SDD 원장은 **육안 확인이 끝난 뒤에** 지운다. 최종 리뷰가 깨끗해도 바로 지우지 말 것.

## 환경 제약 (이번 세션에 다시 확인함)

- **브라우저 창이 이 환경에서 안 열린다.** 이번 세션에도 다시 시도했다:
  `navigate` 가 `navigation ... was denied or failed`, `javascript_tool` 이
  `SecurityError: Failed to read the 'localStorage' property`. `preview_start` 는
  서버를 잡아 주지만 탭이 안 뜬다. 레이아웃·애니메이션·연출은 **전부 사용자 육안 확인**이다.
- 검증 가능한 것: `npm test`, `npm run build`, `node -e`, 파일 직접 읽기.
- **`python` 이 없다.** Windows 스토어 스텁만 있어서 heredoc 스크립트가 조용히 안 돈다.
  파일 수정은 Edit 툴이나 `node -e` 를 쓸 것.
- **원격 저장소가 없다.** 전부 로컬 `master` 에만 있다. 사용자가 "놔둬"라고 했다.

### 개발 서버

포트 5173은 다른 프로젝트(TowerWar)가 잡고 있다. 우리 서버는 `autoPort` 로 5174.

```
이 PC:      http://127.0.0.1:5174/
다른 기기:  http://192.168.1.82:5174/
```

LAN IP는 바뀔 수 있다 (`ipconfig | findstr IPv4`). `preview_start` 가 돌려주는
5~6만번대 포트는 **브라우저 패널 내부 프록시 포트**라 일반 브라우저로는 안 열린다.
사용자에게는 반드시 5174를 알려줄 것.

### 1. 첫 플레이 튜토리얼 (직전 세션에서 이어받아 완료)

[설계](2026-07-30-tutorial-design.md) · [계획](../plans/2026-07-30-tutorial.md)

조준 → 발사 → 장전 → 라운드 클리어 네 단계를 화면 하단 중앙 문구로 가르친다.

| 파일 | 역할 |
|---|---|
| `tutorialState.js` | 단계 전이만 아는 순수 상태 기계. 단계마다 기다리는 이벤트 하나에만 반응한다 |
| `tutorialStore.js` | "봤음"을 `localStorage` 에 남긴다 |
| `tutorialPrompt.js` | 문구를 그린다. 문구는 UI가 갖고 상태 기계는 단계 이름만 낸다 |

**최종 리뷰가 잡은 Critical:** `tutorial` 은 페이지 로드당 한 번 생성되고 항상 `'aim'`
에서 출발하는데, `startGame` 의 `if (!tutorialStore.isDone()) tutorial.reset();` 은
리셋을 *건너뛸* 뿐이라 무효과였다. 튜토리얼을 끝낸 플레이어가 새로고침하면 처음부터
다시 봤다. `tutorialState.finish()` 를 추가하고 생성 직후 게이트했다 (`33018f2`).

설정 패널에 `튜토리얼 다시 보기` 버튼이 있다 (`tutorialStore.clear()` + `reset()`).

### 2. 라운드 진행도와 이어하기

[설계](2026-07-30-stage-progress-design.md) · [계획](../plans/2026-07-30-stage-progress.md)

판을 나가면 무조건 라운드 1부터 시작하던 것을 고쳤다.

- `progressStore.js` — `submitCleared(n)` 이 `max(현재, n+1)` 을 저장한다. 최고점수와
  같은 "더 큰 값만 쓴다" 규칙이라 낮은 라운드를 다시 깨도 안 깎인다
- 저장 지점은 **라운드 클리어 한 곳**, `currencyStore.earn(...)` 바로 옆이다.
  브라우저를 그냥 닫아도 남는다
- `startGame(round)` 가 시작 라운드를 인자로 받는다. 호출부 셋: 이어하기 / 라운드 선택 / 새 게임
- 메뉴는 도달 라운드가 1이면 예전 그대로 `탭하여 시작` 하나, 2 이상이면
  `이어하기 (라운드 N)` · `라운드 선택` · `처음부터` 셋
- `roundSelect.js` — 숫자 격자. **도달 라운드까지만 그린다.** 라운드에 상한이 없어서
  잠긴 칸을 몇 개 보여줄지 정할 기준이 없다. 격자 안에서만 스크롤한다
- `confirmPopup.js` + `gameReset.js` — `처음부터`는 확인을 받고 전부 지운 뒤
  `window.location.reload()` 한다. 스토어들은 상태를 안 들고 있지만 **장착 무기 모델은
  `game.js` 가 이미 로드해 들고 있어서** 새로고침이 확실하다

**지울 키 목록은 손으로 나열하지 않는다.** `gameReset.js` 가 `config.js` 의
`*StorageKey` 이름 규칙에서 뽑고 **최고점수와 마우스 민감도 둘만** 뺀다. 민감도를
남기는 이유는 그게 게임 진행이 아니라 조작 환경이기 때문이다.

**메뉴 ghost 버튼 색 함정 (`b92efc2`):** `.k-btn--ghost` 의 기본색은 `--k-ink`(어두움)라
회색 패널 안을 전제한다. 메뉴 중앙 열은 패널 없이 어두운 3D 장면 위에 놓여서 글자가
안 보였다. 해결책은 이미 있었다 — `k-on-dark` 클래스를 컨테이너에 붙이면
`theme.css` 가 색을 뒤집는다. 새 색을 만들지 말 것.

### 3. 별 4개 무기 '중화기'

[설계](2026-07-30-heavy-weapon-design.md) · [계획](../plans/2026-07-30-heavy-weapon.md)

상점이 별 1·2·3·5로 뛰던 것을 메웠다. `id: 'heavy'`, 데미지 4, 가격 4000,
모델은 저장소에 놀고 있던 `Rifle.fbx`. 저격소총과 레이건 **사이에** 넣었다 —
배열 순서가 곧 상점 순서다.

`test/weapons.test.js` 를 새로 만들었다. id 중복 없음, 가격·데미지 오름차순, 필드 열 개
전부 존재, `format` 이 `glb|fbx`, `scale > 0`, `basic` 이 첫 번째. **앞으로 무기를 넣을
때 이 그물이 자리를 잘못 잡은 것을 잡는다.**

## 확정된 설계 결정 (고치지 말 것)

- **초반 라운드 반복 골드 파밍은 열어둔다.** 라운드 선택으로 낮은 라운드를 반복하는
  것도 포함이다. 사용자가 알고 택했다. 리뷰어가 지적하면 의도된 것이라고 답할 것.
- **`처음부터`는 최고점수와 마우스 민감도를 남긴다.** 나머지는 전부 지운다.
- 장전 슬로모 desync — 그대로 둔다 (직전 인수인계 문서 1번 참고).
- `resetStructure` 가 아직 `group.visible` / `group.rotation.z` 를 만진다. 무해한 잔재.

## 남은 것

### 사용자 육안 확인 대기 (이번 세션 작업물)

- 중화기 장착했을 때 총 크기. **`config.js` 의 `scale: 0.00148` 은 찍어본 값이 아니라
  추측이다.** FBX 무기 배율이 모델 길이 때문에 제각각(0.00061~0.00211)이라 길이가
  비슷한 전기총 값에서 시작했다. 크거나 작으면 그 한 줄만 고치면 된다
- 상점 중화기 칸 그림이 **깨진 아이콘 없이** 비어 있는지
- 3자리 라운드에서 `이어하기 (라운드 100)` 이 320px 버튼에서 줄바꿈되는지
  (`localStorage.setItem('shootshoot.progress','100')` 로 확인)

### 상점 그림 `heavy.png` 가 아직 없다

굽는 순서 (사용자가 브라우저에서):
1. `http://127.0.0.1:5174/thumb.html` 로 512×512 투명 PNG
2. **반드시** `node tools/crop-weapon-art.mjs` 를 한 번 돌린다 — 안 돌리면 정사각
   캔버스 여백 때문에 상점에서 작게 나온다
3. `game/public/images/weapons/heavy.png` 로 넣는다

### 알려진 문제 (그대로 남아 있음)

- **속도와 체력에 상한이 없다.** `difficulty.js` 에서 속도 `0.5 + n×0.08`, 체력
  `1 + floor(n/2)` 로 무한히 오른다. 원숭이 수만 10에서 멈춘다. 장전 0.8초 때문에
  초당 1.25발이 상한이라 어느 시점에 진행이 막힌다. **사용자가 아직 결정 안 함.**
  이어하기가 생겨서 이제 높은 라운드에 실제로 도달한다 — 전보다 시급해졌다.
- 타워 발판이 레이캐스트 대상이 아니다. 발판 밴드를 쏘면 `sfx.miss()` 가 난다.
- 기둥을 얇게 해서 발판이 앞뒤로 0.49씩 튀어나온다. 사용자가 "문제없다"고 했다.
- **지는 조건이 아예 없다.** 원숭이가 도망가지 않고 플레이어가 죽지 않는다. 판이
  끝나는 유일한 길은 `메뉴로` 를 누르는 것이다. 스테이지 게임을 더 밀려면 여기가 다음 축이다.

### 이연된 마이너 (리뷰가 잡았고 안 고치기로 한 것)

- `progressStore` 의 `Number.parseInt` 가 소수 문자열(`'3.7'`)을 조용히 자른다.
  손으로 `localStorage` 를 고쳐야 닿는 경로다.
- `test/weapons.test.js` 의 `toHaveProperty` 는 값이 `undefined` 인 키도 통과시킨다.
- 무기 배열 순서·format·scale 루프의 실패 메시지가 어느 무기인지 안 알려준다.
- `roundSelect` 는 도달 라운드가 500이면 버튼 500개를 그린다. 가상화 없음.
- `game.js` 의 `startGame(round)` 인자가 모듈 변수 `round` 를 가린다.

## 워크플로 메모

- 압축(compaction) 후에는 내 기억보다 `.superpowers/sdd/<plan>/progress.md` 와
  `git log` 를 믿을 것. `complete` 로 적힌 태스크는 절대 재실행하지 말 것.
- **SDD 워크스페이스는 `.superpowers/` 아래이고 gitignore 대상이다.** 커밋하려 하면
  거부당한다. 원장은 로컬 파일로만 남는다.
- 서브에이전트에 **셸 문법 섞지 말라고 명시할 것.** PowerShell here-string 을 Bash 툴에
  넣어 커밋 메시지에 리터럴 `@` 가 박힌 사고가 있었다. `git commit -m "제목" -m "본문"` 으로.
- 서브에이전트에 **브라우저를 쓰지 말라고 명시할 것.** 안 그러면 preview·screenshot 을
  시도하다 시간을 버린다.
- 큰 리뷰는 sonnet 으로. 읽을 파일을 명시하고 "git 명령으로 diff 재유도 금지"를 못박을 것.
  (예전에 opus 최종 리뷰가 세션 한도에 걸려 147k 토큰을 날렸다.)
- **계획서가 틀릴 수 있다. 이번 세션에 실제로 틀렸다.** 스펙과 계획서 둘 다 "그림이
  없으면 `artwork()` 가 숨겨서 자리만 빈다"고 적었는데, `artwork()` 는 `screens.js` 에
  있고 메뉴 바주카 카드 전용이었다. 상점 무기 그림은 리스너 없는 맨 `<img>` 였다.
  리뷰어가 잡았고, 사용자 판정으로 **코드를 문서의 약속에 맞췄다.** 문서에는 틀린
  문장을 지우지 않고 정정으로 남겼다 (`5cb4d80`) — 조용히 고치면 같은 착각이 반복돼도
  흔적이 안 남는다.
- **리뷰어가 좋은 걸 잡아낸다.** 이번 세션 실제 버그 셋: 재방문 플레이어가 튜토리얼을
  다시 보던 것, `lastSeenStorageKey` 가 어느 쪽으로도 테스트에 안 박혀 있던 것,
  위의 `artwork()` 착각. 형식적 절차로 취급하지 말 것.
