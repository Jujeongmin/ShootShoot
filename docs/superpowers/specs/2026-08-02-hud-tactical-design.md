# 전술 계기판 HUD 설계

플레이 중 화면이 심심하다는 요청에서 나왔다. 카운터가 라운드 하나뿐이고 프레임이 없어
숫자가 3D 장면 위에 그냥 떠 있다.

**이건 다시 칠하기다. 게임 규칙과 판정 치수는 하나도 안 바뀐다.**

## 확정된 범위

| 손댄다 | 안 손댄다 |
|---|---|
| 라운드 숫자 (상단 중앙) | P 힌트 (상단 우측) |
| `+점수` 팝업 | 튜토리얼 문구 (하단 중앙) |
| 조준선 — **색과 장식만** | 조준선 **치수** |
| | 메뉴·상점·설정 패널 |

사용자 확정 사항:

- 톤은 **군사/전술 계기판**.
- 팔레트는 **Kenney 노랑을 유지한다.** 전술 느낌은 색이 아니라 형태(브래킷·눈금·자간)로 낸다.
  호박색 인광 계기판과 올리브 스텐실 판도 그려서 비교했고, 둘 다 플레이 화면만 다른 색
  계열이 돼서 메뉴와 언어가 갈라진다는 이유로 탈락했다.
- 브래킷은 **붙은 `[ 7 ]` 모양**. 떨어진 모서리 네 개는 요소가 넷 필요한데 같은 값을 낸다.
- `+점수` 팝업은 **보통·헤드샷·관통 세 종류를 구분한다.**

## 왜 팝업 세 종류가 범위 안에 들어왔나

처음 정한 범위는 "지금 있는 것만 다시 그린다, 정보를 새로 안 띄운다"였다. 세 종류 구분은
엄밀히 새 정보라 따로 확인을 받았다. 근거는 둘이다.

1. **값이 이미 손에 있다.** `game.js` 의 `finishShot` 은 팝업을 띄우기 두 줄 위에서
   `effectiveOutcome.penetrationCount` 와 `effectiveOutcome.hits[0]?.part` 를 이미
   읽고 있다 — 효과음을 고르려고. 새로 계산할 것이 없다.
2. **소리는 이미 구분한다.** `sfx.combo()` / `sfx.headshot()` / `sfx.hit()` 셋이 난다.
   화면만 안 따라가고 있었다.

## 무엇이 어떻게 보이나

### 1. 라운드 숫자

```
── 라운드 ──
 [    7    ]
```

- 라벨 `라운드` 양옆에 14×2px 노란 막대 (`--k-shadow`). 기존 자간 2px 유지.
- 숫자는 기존 `.k-round` 그대로 — 44px, `--k-face`, 3중 그림자. **한 픽셀도 안 바꾼다.**
- 숫자를 감싸는 `[ ]` 브래킷이 새로 붙는다.

### 2. `+점수` 팝업

| 종류 | 조건 | 모양 |
|---|---|---|
| 보통 | 그 외 전부 | 지금 그대로 — 글자 `--k-face`, 24px |
| 헤드샷 | `hits[0].part === 'head'` | `[ +120 ]` — 글자 `--k-hi`, 26px, 브래킷은 `--k-face` |
| 관통 | `penetrationCount > 1` | `+240` — 글자 `--k-hi`, 28px, 아래에 2px `--k-face` 눈금 줄 |

브래킷은 글자보다 한 단계 어두운 `--k-face` 를 유지한다. 글자와 같은 `--k-hi` 로 두면
테두리와 숫자가 한 덩어리로 뭉쳐서 브래킷이 안 읽힌다.

**우선순위는 관통 > 헤드샷 > 보통이다.** `game.js` 의 효과음 분기와 같은 순서여야 한다.
관통하면서 헤드샷인 발사는 소리가 `combo()` 로 나므로 화면도 관통으로 보여야 한다.
이 순서는 커밋 `54fa697` 에서 한 번 어긋났던 자리다 — 통로를 무너뜨려 둘을 죽였는데
콤보 효과음이 아니라 단발 효과음이 났었다. 같은 실수를 화면 쪽에서 반복하지 말 것.

떠오르며 사라지는 동작(0.6초, `translate(-50%, -120%)`, opacity 0)은 세 종류 모두 같다.

### 3. 조준선

**치수 동결.** 바주카 조준선의 네 모서리 브래킷은 판정 사각형의 경계 그 자체다.
`radiusPx` 와 `arm` · `tickLength` · `tickOffset` 계산에 손대지 않는다.

바꾸는 것은 둘뿐이다.

- **어두운 외곽선.** 막대마다 `box-shadow: 0 0 0 1px rgba(0,0,0,0.55)`. 흰 조준선(`basic`)이
  밝은 하늘 위에서 사라지는 문제가 실제로 있다. `box-shadow` 는 레이아웃을 안 바꾸므로
  치수가 그대로다.
- **팔 안쪽 끝 눈금.** 십자 팔 네 개의 **안쪽** 끝(중앙 쪽)에 짧은 직각 눈금을 붙인다.
  길이 10px, 두께는 팔과 같은 2px, 색도 팔과 같은 `crosshairColor`.
  바깥쪽 끝은 70vmin 상자의 가장자리라 화면 구석이다 — 거기 눈금을 달면 안 보인다.
  안쪽에 달면 조준점을 네 개의 T자가 감싸는 거리계 모양이 되고, 바주카 조준선이 이미
  쓰고 있는 눈금 언어와 맞는다.

  팔의 안쪽 끝은 상자 가장자리에서 38% 지점이다 (`height: 38%`). 눈금은 거기 붙으므로
  중앙 점과는 상자 크기의 12%만큼 떨어져 있다 — 조준점을 안 가린다.

## 구조

브래킷을 두 곳(라운드 숫자, 헤드샷 팝업)이 쓴다. **구현은 하나만 둔다.**

| 파일 | 역할 |
|---|---|
| `ui/theme.css` | 모양 전부. `.k-bracket` 하나와 팝업 세 클래스 |
| `ui/hud.ts` | 클래스 이름만 붙인다. 지금 인라인 `cssText` 로 박힌 팝업 스타일을 클래스로 옮긴다 |
| `ui/scopeOverlay.ts` | 색·외곽선 상수와 눈금 마크업. 치수 계산 함수는 안 건드림 |
| `ui/scorePopupTone.ts` | **신규.** 순수 함수 하나 |
| `gameplay/game.js` | `showScorePopup` 에 톤을 하나 더 넘긴다 |

### `.k-bracket`

의사 요소 둘로 `[` 와 `]` 를 그린다. 각각 세 변만 그리고 안쪽 변을 지운다.

```css
.k-bracket { position: relative; display: inline-block; padding: 0 0.32em; }
.k-bracket::before,
.k-bracket::after {
  content: ''; position: absolute; top: 0; bottom: 0; width: 0.2em;
  border: 2px solid var(--k-face);
}
.k-bracket::before { left: 0; border-right: none; }
.k-bracket::after  { right: 0; border-left: none; }
```

**치수를 `em` 으로 두는 이유:** 이 클래스를 44px 라운드 숫자와 26px 헤드샷 팝업이 같이
쓴다. `px` 로 박으면 둘 중 하나에서 브래킷 비율이 어긋난다. 테두리 두께만 2px 고정인데,
그건 선이 굵기로 읽혀야 해서다 — 26px 쪽에서 1.2px 로 얇아지면 흐려 보인다.

요소를 안 늘리는 게 핵심이다. 떨어진 모서리 네 개를 원하면 `div` 둘을 더 넣어야 한다.

### `scorePopupTone.ts`

```ts
export type PopupTone = 'normal' | 'head' | 'combo';

export function scorePopupTone(outcome: {
  hits: { part: string }[];
  penetrationCount: number;
}): PopupTone;
```

**이걸 따로 빼는 이유는 테스트다.** HUD에는 지금 테스트가 하나도 없다. 우선순위 규칙을
순수 함수로 빼면 단위 테스트가 붙고, `hud.ts` 에는 DOM 조립만 남는다.

`hud.ts` 의 `showScorePopup(text, clientX, clientY)` 가 네 번째 인자 `tone` 을 받는다.
기본값은 `'normal'` 로 둬서 호출부 하나만 고치면 되게 한다.

## 실패와 경계

- **팝업이 미명중일 때는 아예 안 뜬다.** 지금 `game.js` 가 `!isMiss && gained > 0` 일
  때만 부른다. 톤 함수는 이 경우를 볼 일이 없지만, `hits` 가 빈 배열이면 `'normal'` 을
  낸다 — 방어적으로.
- **`hits[0]` 만 본다.** 관통해서 여럿 맞으면 우선순위상 어차피 `'combo'` 다.
  효과음도 `hits[0]` 만 본다. 같은 규칙을 쓴다.
- 브래킷 색은 `--k-face` 고정이다. `k-on-dark` 뒤집기 규칙에 안 걸린다 — 브래킷은
  3D 장면 위에만 놓이고 회색 패널 안에는 안 들어간다.

`ui/scorePopupTone.ts` 는 처음부터 `.ts` 로 만든다 — 마이그레이션 Task 4가 이미
`ui/` 를 전부 옮겼으므로 `.js` 로 만들면 되돌아가는 것이다.

## 이 설계가 손대지 않는 것

- 게임 규칙·수치·난이도 일체
- 조준선 치수, 특히 바주카 판정 사각형
- P 힌트, 튜토리얼 문구
- 메뉴·상점·설정·라운드 선택 패널
- 점수·연속타·남은 원숭이·장전 상태를 화면에 새로 띄우는 것 — **범위 밖이다.**
  나중에 하고 싶으면 별도 설계로 다룬다
